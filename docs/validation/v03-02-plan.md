# V03-02: 削除を含む変更での独立比較

**方針：Sekka固有の貢献を確かめる場合は、通常diffを読む前の候補を保存し、その後の確認結果と区別する。**

2026-09-08、[#50](https://github.com/KantoYamamoto/sekka/issues/50)。以下の条件はIssueに記録し、結果受領前に固定した。#10の削除比較の一例で、M2全体の完了とはしない。

## 選定と固定入力

公開[kean/Nuke PR #963「Remove the rate limiter」](https://github.com/kean/Nuke/pull/963)。タイトル・規模メタデータから、削除された役割と残る処理を照らす課題に選んだ。選定時点で調整担当はこのPRの差分・本文・既存レビューを読んでいない。前回Nuke #953での周辺知識はある。

- base: `bbbb53475d1b48e1d64891ccfd632ac85fc61c5c`
- head: `9ee5994d613854c03acec20a4baf4715f34f5a49`（merge-baseは上記base）
- Swift12ファイル、全15パス。Swift diff408行・17,171 bytes、その他のdiff40行。
- 評価器: Sekka `b25e90b`のSwift実装、記録commit `eea9291`。バイナリSHA256 `e43a9ae5edfbeb5cd0958bb29546958e44b027e7654be7fab9747c119ab535d4`。

`.build/independent-review/nuke-963/{A,B}`へ同じdiff・固定入力metadataを置き、Bにtext/compact/fullとバイナリを追加した。各packetのSHA256を照合した。Gitはpartial cloneではなく全取得し、到達可能オブジェクトにmissingがないことを確認した後、A/B別のno-checkoutコピーを作った。レビューでは固定SHAのgit show/grepを使う。準備中のbare repoではSekkaが起動できず、配布前に通常repoへ変更した。対象コードは実行していない。

## 課題と手順

削除された役割・制御と残る処理、利用側・テスト・文書の整合を確認する場所を、事実・問い・不足文脈に分けて最大5件選ぶ。不要な機能が妥当に削除された可能性も検討し、バグを作らない。

Aは通常Swift/その他diffから開始。BはSekka textを読み、diffを読む前にcheckpoint.mdへ候補を保存してから、通常diffと周辺コードで確認する。両担当は同じ親設定から会話履歴を渡さず作成し、モデル・推論設定の個別上書きはしていない。正確なモデルIDやtoken数を測定できなければ推測しない。

他packet・Sekka開発記録・PR議論・既存レビューを読まず、対象のビルド/テストもしない。開始/完了時刻、追加検索と目的、読取り順・失敗・中断を記録する。15分程度と検索10回は目安で、必要な確認を省く強制上限ではない。調整担当は両結果受領後に通常diffと根拠を読み、具体的な助け・負担・根拠のない候補を照合する。

## 実施中に判明した制約

利用上限によるエラーと再開が発生した。両担当の時計にも09:51 UTCから14:53 UTCへの空白があり、実作業と中断を分離できないため速度比較には使わない。固定packetとBの先読みcheckpointを維持し、結果を根拠と到達経路の比較として扱う。これは「速度が改善した/悪化した」という結論を支える実験ではない。
