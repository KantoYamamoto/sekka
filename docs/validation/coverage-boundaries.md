2026-09-07。Issue #21。Sekka `6bb4c12`の評価器。合成15種類は単一の既知変更に対する観測を調べる試験で、レビュー時間・意味的な網羅性の証明ではない。

## 合成15種類

[再実行ケース](../../Fixtures/probes/cases.json)と[runner](../../Scripts/review_probes.py)。期待終了コードは全15件一致。ここでの成功は解析の終了状態が想定どおりだったという意味で、変更をすべて案内できたという意味ではない。

| ケース | 結果 |
| --- | --- |
| body-threshold | 本体のトークン変更として関数へ案内 |
| stored-threshold | ファイル変更のみ。初期値の位置は未案内 |
| mixed-initializer | メンバー追加のみ観測。初期値変更は個別に見えず、未観測ファイル一覧からも外れる |
| top-level | ファイル変更のみ。関数の位置は未案内 |
| call-argument | 呼び出しを含む関数へ案内。引数の正誤は不明 |
| enum-value | 宣言差分としてraw valueを表示 |
| default-argument | 引数差分を表示し、本体比較省略を明示 |
| computed-property | computed propertyのトークン変更へ案内 |
| swiftui-extraction | 既存body変更と追加propertyへ案内。分割の妥当性は不明 |
| type-move | 型追加・削除の別観測。移動同一性は推定しない |
| type-delete | 20本体の比較省略をtext 1件にまとめ、JSONに20件保持 |
| forwarder | そのまま渡す構文を観測。不要な抽象化とは判定しない |
| inactive-branch | ビルド条件にかかわらず本体変更へ案内 |
| comment-only | ファイルは変更あり、syntaxChanged=false |
| invalid-source | 終了コード2。部分的な観測なしを成功にしない |

関数本体のトークン差はfindingsが0でもbodyComparisonsから個別案内される。したがってfindingsの数だけを「検出数」として採点しない。

### 最も気になった盲点

`mixed-initializer`では、既存メソッドはトークン一致、追加メソッドは比較相手なしとなる一方、stored initializerの3→8に個別の記録がない。ファイル全体のsyntaxChangedはtrueだが、メンバー追加の観測1件があるため未観測ファイル一覧にも出ない。現行の「Scopeは限定的」という説明は正しいが、読むべき差分を絞る道具として場所の説明が不足する。

## 実変更2件

| ケース | Swift差分 | text | 構造観測 | 読めたことと限界 |
| --- | ---: | ---: | ---: | --- |
| SwiftUIのファイル分割 | 121,304文字 | 29,553文字 | 20件 | 元ファイル10型の削除と移動先10型の追加。前後で同名型の宣言要約は10組すべて一致したが、本体126件は未比較 |
| 評価失敗時のガード追加 | 7,686文字 | 2,096文字 | 2件 | ユースケース本体と失敗時テストが確認先になった。ガードとその先へ渡す引数は通常diffで確認 |

分割ケースでは、通常diffの追加・削除行を多重集合で照合して再配置の様子も確認した。ただし順序や本体同一性を保証する検査ではない。案内は移動候補の一覧にはなるが、同じ宣言の全文が前後に並ぶため、短い「どこからどこへ」の案内にはなっていない。タイトルに挙動不変とあっても、Sekkaでそう検証できたとは言わない。Swift以外のデータ変更も混在していた。

ガード追加では、案内したafter:54と入力IDを指定してhunkを取得し、成功時の更新ガードと推薦へ渡す引数の変更に到達した。通常diffで、追加テストが能力値・表示用差分・新規レコード数を検査していることまで読めた。2件の観測だけからその保証内容は分からない。今回は案内→確認箇所の流れを試せたが、独立した時間比較ではない。

## 次の判断

1. [Issue #22](https://github.com/KantoYamamoto/sekka/issues/22)で、観測済みファイル内に混在するstored initializer変更の個別案内を優先検討する。閾値の善悪を判定せず、変更した宣言位置を示す案。
2. 大量移動の短い案内は次候補。ただし名前一致だけで移動や挙動同一と断定しない方式が必要。
3. 未対応領域全体を網羅したという表示や、自動の設計スコアへは進まない。独立したM2比較は依然未完了。

根本の「事実から読む場所を選ぶ」という方針は維持する。ただし観測項目数や出力文字数の改善だけでは足りず、同じファイル内の未観測箇所が分かるかを次の投資判断に含める。
