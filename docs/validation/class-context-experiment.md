# 追加型と既存の実装配置を結ぶ実験

2026-09-09、[#57](https://github.com/KantoYamamoto/sekka/issues/57)、判断[0034](../decisions/0034-class-context-experiment.md)。本番未採用。#56の実例で、呼び出し反復ではなく空の共通入口と既存兄弟の実装が配置の問いの根拠になったため、実験を置き換える。

## 変えたもの

新しいclass名から、入力内に前後とも一意なclass宣言のある親候補と既存兄弟候補を探す。親の空bodyと兄弟のoverrideに同じメソッド表記がある場合、追加型側の宣言も並べる。型解決・実装不足・必要な共通化は断定しない。

新しい処理がないという判定にしないため、bodyなしの宣言もunavailableとして残し、名前と引数ラベルが同じでも型等の表記が違う場合は別欄へ出す。同名・条件付きメンバー・限定付きextension等で候補を絞れない場合は、前後を区別して省略理由を残す。

旧CallSequencesのSwift packageと常設CIは撤去した。既存のディレクトリ入力の境界だけを引き継ぎ、JSONは関係の組へ変更した。旧実験は[固定commitでの再現](../../Experiments/CallSequences/README.md)と検証記録を残す。小さな試作を第2・第3の製品として並行保守しない。本番SekkaのCLI/schemaは変更していない。

## 試験と修正

- Swift 16テスト：未変更親/兄弟の位置、追加型にも実装がある対照、意図的な空hook、複数ファイルのextension、同名・generic・qualified名・型/ラベル/効果の差、構文エラー、JSON順序。
- CLI：前後ファイル数、同一入力と繰り返し実行の安定性、dot名の祖先/ルート・Finder非表示属性、部分出力のない構文エラーとsymlink拒否。
- 固定OSS入力：manifestの全Swiftパス/SHA-256と収集件数を照合し、代表メソッドの行位置と別表記の宣言を確認。対象コードは実行しない。
- 本番：Swift 65テスト。CLI/Gitチェックも実行し、結果を自己利用記録と照合する。

初回は関数本体内の#ifまで型の候補除外に使い、WordPressの親を落として0組になった。これは宣言の存在条件と本体の条件を混同したため。メンバー宣言を分岐する#ifだけを候補除外へ使い、両者の対照テストを追加した。

独立実装レビューでは、bodyなし宣言を捨てると「入力内に一致宣言なし」が事実と違うことを確認・修正。再レビューで解消を確認した。前後の候補除外理由と説明のずれも修正した。

## 固定実入力の結果

| 入力 | 関係の組 | メソッドの組 | 解釈 |
| --- | ---: | ---: | --- |
| WordPress #25208、15→16 Swiftファイル | 1 | 8 | 新しいCustomPostEditor、親PostGBKEditor、既存NewGutenbergEditorを結ぶ。媒体要求の親145行・兄弟262行は#56の問いの位置と一致 |
| Firefox #34338、2→2 Swiftファイル | 0 | 0 | 新しいclass名がないため対象外。局所追加の妥当性を自動で判定した結果ではない |

履歴イベントでは親のGutenbergKit.EditorStateと追加型のEditorStateの表記が違う。名前/ラベルが一致する別表記として追加型67行を添える。意味的に同じ型とは解決しない。8組には媒体選択以外のイベントも含み、全件が設計上の問題という意味ではない。

未変更helperのAbstractPost→Blogという依存縮小の根拠は、この試作には含まれない。親・兄弟の配置の入口を出せても、具体的な移動方法の検討にはソースを読む必要がある。WordPressは実装の選定に使った既知入力で、検出できたことを未読入力での有用性へ一般化しない。
