# 0048: 差分外の根拠を未変更宣言だけに限定しない

**方針：配置の問いの根拠が変更された既存窓口にある場合は、宣言全体の不変を前提とする検索へ継ぎ足す前に、観測単位を診断し直す。**

- 記録日：2026-10-05
- 状態：診断方針採用・runtime契約変更と本番採用は未決定
- 経緯：#102の独立sourceレビューから。既存の[差分外context方針0038](0038-outside-diff-context.md)を目的へ戻して具体化。前後call入口[0047](0047-both-side-call-entry.md)の実装結果は保持する。

## What / 目的

通常diffだけではつながりが見えにくい既存構造を補い、「継ぎ足しより既存窓口へ組み込むか」を考える材料を示す。未変更宣言への到達は一つの手段で、成功条件そのものではない。関数/initializer/計算property等の実行領域、同種の変更が入る場所、既存helperと利用側を、変更状態と未解決を添えて観測できるかを[診断 #105](https://github.com/KantoYamamoto/sekka/issues/105)で確認する。

## Why / 観測済みの理由

[比較 #102](../validation/both-side-call-holdout.md)のGRDB #1885で、Bは通常sourceからscalarの結果転送を既存reportへ揃える限定的な問いを立て、Aは主要規則が既に共有され必要性不足と判断した。機械出力は0。report自体は既存だが本体変更、scalarはinitializerで、現在の不変target/関数中心の範囲ではこの問いを案内できない。必要性の判断差は残すが、具体的な未到達関係を診断できる。

宣言全体の不変は「この宣言は変わっていない」という事実を守るための条件である。差分外に必要なbodyや既存窓口が存在することまで、その条件で限定する理由にはならない。必要な材料を示す目的へ立ち返る。

## Why not / 採らないこと

call名や役割の推測ruleを重ねて既読のreportだけ拾う方法、本体が似るから共通化必須とする判定は採らない。引数値・receiver・型・SDK意味・性能が異なる可能性を保持する。新しいString helperへ主要処理が既に集約されていることも反対材料である。

#102のstage1はAだけ通常diffを先渡しした手順の相違があるため、純増利益の肯定/否定へ使わない。未到達のsource事実を診断することと、新方式の未読比較を分ける。後続比較は両stage1に同じ通常diffを渡す契約を閲覧前に固定する。

## How / 終了と分岐

#105では既知必要位置を先に固定し、実行領域の未索引・変更targetの除外・記載関係や対応の不足を分離した。単にinitializerを追加しても変更されたhelperの除外は残るため、switch構文形の前後変化を別単位で診断。既読1例で2領域/既存property利用表記へ到達、他2例0。引数/条件差と共有済み主処理を反対材料として保持する。[診断結果](../validation/cochange-diagnostic.md)。code/fact/文書独立点検・26対照・自己利用は完了、最終PR点検は進行中。対象build/LLM/意味解決は使わない。

事実性と必要関係への到達が成立した場合だけ実験CLIの組み直しを分解する。似た構文の不要接続や不明が中心なら撤去/再設計、範囲だけ広がるなら用途限定/保留へ戻る。独立比較でも配置再考への寄与が得られず別の決定論的根拠もなくなった場合は、ユーザーの依頼に従い用途限定/プロジェクト撤退を人間へ判断事項として知らせる。M3は保留。既読例への到達を未見の有用性とせず、診断・独立点検・PRの実Actions/成果物までを一単位にする。
