# 0017: 型参照サイトの宣言反復をまとめる

**方針：同じ宣言の型参照が複数行に出る場合は、前後それぞれ宣言を一度だけ表示し、役割と型表記をその下に列挙する。**

- 記録日: 2026-09-07
- 状態: 採用
- 経緯: Issue #19の未試用PR予備試行で長いinitializerが各参照行に繰り返された。

## What / Why

型参照サイトのtext差分を、削除・追加のそれぞれで完全一致するmemberごとにまとめる。長い宣言の反復を減らして、その後の引数差分・本体案内へ進みやすくする。役割・型表記の違いはすべて残す。

## Why not

参照サイト全体を件数だけにすると、どの宣言からどの役割の参照が変わったか読めない。宣言名だけで前後を対応付けるとoverloadや引数変更を同じものと推測してしまう。表示済み文字列の分解はdefault値や属性に含まれる文字との衝突を招くため使わない。

## How

構造化されたReferenceのmember/role/spellingで差集合を作り、memberごとにソートして出す。行位置だけの差は従来どおり観測差としない。異なる宣言は前後をまたいでまとめない。1参照の宣言は従来の1行表示。Findingの内部表示情報をJSONから除外し、JSONの完全な前後の参照・件数・本体比較状態は変更しない。デコードしたFindingには内部情報がないため従来の全文表示へ戻る。

## 制約・見直す条件

型表記は解決済み依存関係ではない。変更した引数に由来する参照差の重複自体は残る。短縮が独立したレビューの手間削減になるかは未検証。情報保持・出力量・自己利用の結果を[予備試行](../validation/review-pilots.md)に残す。
