# 0043: 条件付きの接点は字句条件とともに示す

**条件内に書かれた接点は、選択節・先行節の表記と位置を入口へ添え、異なる条件の出現をまとめない。条件の有効性は推測しない。**

- 記録日: 2026-10-01
- 状態: M2実験。#89 / 0042の具体化。本番統合は保留

## 目的 / What

Collections #724の比較で、未変更buffer helperへの表記が`#if false`内だった。差分外の契約は配置比較に使えたが、入口の条件を表示しないと現役の共通経路と読み替え得る。件数を増やす前に、既に示す根拠を照合できるようにする。

callごとに外→内の選択節、elseif/elseに先行する節、条件のトークン表記とheader位置をJSONへ保持する。textでも同じ位置と「有効節未判定」をcallのそばへ示す。同じcaller/receiver/selectorでも条件なしと条件あり、異なる条件は別入口。同じ表記の条件は位置が違ってもまとめ、最初のcall位置と件数を示す。

## Why / Why not

`#if false`を捨てる方式は過去の代替実装への接点も消す。Swift/compiler/platform設定の推測は決定論的なソース観測とは別の意味解決を持ち込み、対象ビルド不要という境界を変える。全branchの表記を読み、判断材料として条件を示す。

条件移動だけで同じcallを再検出する案や、類似度/scoreで候補を増やす案は今回混ぜない。条件表示が正しくても、共有の先例や反復負担への未到達は別の課題として残る。

## How / 限界

既存scope索引のAST祖先/先行節の読み取りを`WrittenConditionalContext`へ移し、既存の前後対応キーを維持する。自己利用で残存した単なる転送を確認し、InventoryReaderから共有処理を直接参照する。callの条件根拠も同じ読み方で作り、集約キーには位置を含めず条件表記列を追加する。新旧callトークンの適格性、候補一意性/未変更判定、上限は維持する。

local関数/型の本文は混ぜず、closureの表記は含む。型表記/既存call接点の経路へ暗黙に同じ機能を拡張しない。条件の同値性、active branch、receiver型/実calleeは解決しない。同条件groupの全位置/異なる引数は列挙しないため、件数を挙動の反復と解釈しない。

## 確認 / 見直す条件

[検証](../validation/written-conditional-context.md)で合成対照、既知4PR、独立レビュー、自己利用を記録する。既知入力を未見として再採点せず、条件が見えることを構造検討の成功には数えない。必要な未変更実装へ届かない場合は検索単位の見直しへ戻る。
