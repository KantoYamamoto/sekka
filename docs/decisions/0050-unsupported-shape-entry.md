# 0050: 未見比較が支持しない入口は拡張せず、必要な関係へ戻る

**方針：正常に動く入口でも未見の配置判断へ寄与しない場合は、その統合・高速化を止め、実際に必要だった関係の表現可能性を一単位で診断する。**

- 記録日：2026-10-07
- 状態：#109 / PR #110、#111 / PR #112完了。新入口の#113限定比較と次の境界は[0051](0051-state-context-investment.md)。本番/M3保留
- 根拠：[未見比較](../validation/direct-relations-holdout.md)、[旧減少call診断](../validation/withdrawn-entry-diagnostic.md)、[両側入口比較](../validation/both-side-call-holdout.md)

## What / 目的

4件とも直接関係0で、機械由来の必要入口・配置判断の材料を得ていない。同形switch変更という検出条件を、Sekkaの成功条件として扱わない。現runtimeは再現可能な実験として凍結し、本番へ移植しない。次はGRDB1881の「専用操作を増やすか、既存汎用合成を改善するか」という問いに必要な、差分外の汎用操作・既存利用側の関係を診断する。

## Why

その問いは通常diff/sourceから出た。新insert、旧formUnion/union、同じ領域データと既存の反復利用が根拠で、複数switchの同じ形変化ではない。既存構造を見直す必要がないという結論を支える共通処理も、他3件では普通の検索で確認している。案内件数を増やすことや52〜97秒のdebug実行を先に速めることは、必要関係を示すという未達を解消しない。

## Why not

旧#96/#100の減少call検索を復元すれば解決、とも扱わない。旧方式は利用が減った表記と一意の未変更窓口を起点にし、既読の先例には届いたが未見の配置判断への寄与は支持されなかった。今回もformUnionという名前だけでは、汎用合成と専用操作が何を共有し、どの既存利用が残るかは分からない。既知1件にruleを合わせる、同じ入力を未見扱いする、設計警告を推測で作る、曖昧な同名callを実依存にする案を採らない。

## How / 診断の境界

[#111](https://github.com/KantoYamamoto/sekka/issues/111)で実装前にこのcaseの必要な位置・差分露出・問い/反対理由を固定する。新しい最小試作は「変更で追加された操作と既存操作が、同じ字句owner内のどの記載データを参照するか、その既存操作にどの利用表記が残るか」を入口にする。宣言、記載参照、候補関係と不明を示すだけで、実型・実callee・役割同一・純粋性・負債を判定しない。旧方式のcode契約は重複実装を避ける参考にするが、利益未支持の方式の再build/追加実験を着手条件にしない。2026-10-07の委任に従い、継続より新方式の方が妥当ならそちらを選ぶ。

shadowing、別owner/extension、overload、条件、computed property、自分の状態を直接触らない処理では単純な表記一致が壊れる。これを自分の合成対照と同じ既読素材で点検し、対応できないものは明示する。特に「同じデータを使う」だけでは共通化を要求しない。既存の専用操作で影響範囲を狭める反対理由を保持する。

診断結果が必要な差分外関係を表現できず、別の具体的な根拠も残らなければ、機能を追加し続けず用途限定/撤退を人間へ判断事項として通知する。表現できても有用性は未確立で、別の固定未見比較が必要。直近の診断だけをIssueへ分解し、本番統合や配布のタスクを先に増やさない。Logger/Analyticsの責務一致全般を解決する案とはしない。
