# 判断記録

**実装方針を選ぶ・変える場合は、その変更と一緒に判断と理由を残す。**

目的は、後から「何をしたか」だけでなく「どの問題のために、なぜこの案を選んだか」を追えること。使い方はルートREADME、未採用案は [ideas.md](../ideas.md)、実験結果は各検証レポートに置き、ここから参照する。

## 書き方と更新方法

- [テンプレート](TEMPLATE.md)を使い、`連番-短い名前.md` に1判断を記録する。先頭の方針は「こういう場合はこうする」の一文にする。
- 各項目はまず1〜3文で具体的に書く。Why notは実際に検討した別案と今回採らない理由を書く。比較していない案を後から検討済みと装わない。
- 利用者に見える挙動、解析精度、対象範囲、出力形式、依存や運用条件の選択は記録する。変数名の変更などは新しい記録を増やさず、必要なら関連記録へ補足する。
- 実装・テストを進める中で更新し、同じコミットに含める。未検証事項は未検証と書き、結果が出たら根拠へ追記する。
- 採用案を変更する場合は新しい記録を追加する。旧記録の理由は消さず「置換済み」にし、旧→新・新→旧のリンクを付ける。目次にも状態を反映する。
- 「提案」「採用」「置換済み」を区別する。記録日は記録した日とし、判断日が不明なら推測しない。
